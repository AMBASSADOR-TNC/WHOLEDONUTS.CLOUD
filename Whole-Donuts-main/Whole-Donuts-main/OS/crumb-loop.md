# CRUMB LOOP (CL-∞)

**Specification only, not a deployed service.** The cycle and outputs below are
design goals, not running behavior. See the [Bathroom Door safety boundary](crumb-code.md#bathroom-door-safety-boundary).

The Crumb Loop is the circulation engine of the Crumb Saver.
It keeps crumbs moving, resurfacing, evolving, and transforming forever.

## Purpose
To ensure every crumb stays alive inside the ecosystem and continues to generate value.

## The Loop Cycle

### 1. Surface
A crumb rises from the Vault or Pipe.

### 2. Review
Crumb is examined for relevance, potential, and lane alignment.

### 3. Shape
Crumb is refined into a clearer form:
- phrase
- concept
- draft
- micro-product seed
- helper action seed

### 4. Route
Crumb is sent to the correct subsystem:
Whole Donuts Cloud / Sunshine / ACCESS / Domain / Donor / OS.

### 5. Build
Crumb becomes a structured asset:
- PDF
- helper action
- domain page
- OS module
- donor perk
- movement language piece

### 6. Integrate
Asset is added to the ecosystem:
- published
- activated
- deployed
- linked
- embedded

### 7. Return
Crumb (or its evolved form) returns to the Vault for future resurfacing.

## Loop Behavior
- The Loop never stops
- The Loop never loses crumbs
- The Loop evolves everything
- The Loop feeds the Vault
- The Loop feeds the Pipe
- The Loop feeds the OS
- The Loop feeds the ecosystem

## Loop Output
- New helper actions
- New micro-products
- New domains
- New OS modules
- New donor flows
- New movement language
- New ecosystem expansions

## Status
Crumb Loop is not operational. No background loop, automatic resurfacing,
publication, deployment, donor flow, or rewards service runs from this specification.
